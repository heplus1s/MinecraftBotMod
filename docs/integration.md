# Resident API v2 · 集成边界

`dev.societybots.core.api.ResidentApi` 是不依赖 Minecraft 的接口。银行、领地、收费、交通、订单和本地模型各自通过独立适配层接入；Minecraft 内的发现入口和 mod 间注册尚未实装。新增模块注册一次自己的 `命名空间:动作`，不改游戏命令，也不让模型编写任意 Java/服务器命令。Adapter 缺席时，对应能力不可用。

| 模块 | 输入 | 职责 |
|---|---|---|
| 世界与交通 | 同维度当前位置、已加载地形、可用车船、目标编号 | 计算安全路径；不强制生成区块或用瞬移完成任务 |
| 领地与工作 | 居民 UUID、目标方块或容器 | 执行前复验权限、矿区和物品状态；来源不明一律不挖 |
| 银行、商店、市场 | 居民 UUID、交易授权、报价、结算引用 | 查价和回执；使用普通玩家流程；不能把未知回执作为失败重扣 |
| Ollama 或其他模型 | 状态摘要、任务及能力说明、对话文本 | 可提出新目标和组合步骤；只输出建议和对话；异步、限并发、可停用 |
| 渲染与运行预算 | 客户端显示档、在线居民上限、区块及路径预算 | 显示不改变权限及实体物理；到上限降载或暂停 |

对话与任务是两条入口。普通聊天不能转为扣款或管理员授权。计划包含观测版本，世界或权限变化后拒绝旧计划。可将工作排程换成规则或本地模型，但领地、收付、库存、交通安全检查不能替换。

## 视觉与实际内存

计划提供正常、简化和不显示三档，当前只定义配置类型，不宣称客户端显示已实现。基础版将保留原版客户端兼容；需要更精细的按玩家隐藏或自定义模型时，在测试服单独验证网络跟踪影响。游戏贴图在客户端渲染。服务端内存重点是在线居民及它们保持加载的区块、实体和历史记录。完整假玩家可能使用原版玩家的区块票据；每居民限制加载范围必须通过适配实测，否则使用全局并发限制和闲置暂停，不把纸面区块上限当成已生效。

## 外部服务必须到场

沿用既有部署，不添加实体柜台。服务端从 **Bot 本人** 的位置观察同维度、四格以内、未被遮挡的已登记实体；探针不右键、不打开 GUI、不付款。悬浮文字、模型输出或管理员位置都不是到场证明。未加载区块、已拆除或不兼容的服务点应拒绝。对实体网点的有效性检查不能代替原模块的普通玩家权限规则。

真实服务接入时用 `registerAtCounter` 与 `CounterVisit.atDeployment`，在服务端校验本人到场，并在 `dispatchAtCounter` 消费一次性凭证时重新检查同一实体、引用、普通权限和现有位置；不依赖客户端 GUI、不能使用远程交易指令替代。报价、确认、进桌等必须分别核验。游艺厅兑入和兑出只在兑换柜台，游戏只在匹配玩法的桌旁；续局绑定同一桌和本次会话。真实收付由原模块的账本负责，未知回执必须核对，不重扣。独立 Bot 的领地审批仍在 BotMod，批准不代替到场；收费点走正常通行逻辑，不因实体接入重复扣款。

「贪婪」是游艺意向，不是资金或操作授权。不替换用户授权、空闲条件、储备金、支出上限或冷却校验；不能改变游戏规则。没有接入实际结算或未启用时，Bot 不消费。

## 普通玩家身份是执行条件

管理员只配置或审批，执行者始终是已登记、在线、当前会话中的 Bot。具有 OP 名单身份、提权、创造或旁观状态的 Bot 一律拒绝执行。扩展动作须先通过同一个实时身份检查；禁止以管理员或主人的命令源提交，禁止 OP、后台指令、强制传送和跳过原有权限。普通 Bot 身份也不意味着具备柜台、领地、库存或账目权限，实际操作需另外核验。

发布前验收：短期提升 Bot 权限后，现有计划应失效，不能进入管理命令，也不能提交扩展操作；恢复为普通状态后，必须重新核验原服务权限。没有完成实机验收前，不发生产包。

## 首次生成与激活

`FirstJoin` 先核对保留的 Bot 档案和安全出生点，再调用生成适配器；只有返回的身份、会话、落点、生存状态都符合才能激活。Carpet 1.4.112 先登记实体再设置模式，不能把初始加入回调当成已激活；不能调用不带完整参数的 Carpet 生成指令。适配器还要防止复用现有玩家 UUID 或读入旧玩家数据，并遵守服务器封禁、白名单和普通玩家领地规则。失败只可清理本次确知未激活的假玩家会话；异常或身份不一致时先核对，不按名字踢人或重试。这里是已测的核心流程，不代表实际 Carpet 适配器已上线。

实机验收门槛和候选提交要求见 [发布前验收](acceptance.md)。
