# MinecraftBotMod · 服务器居民

面向 Minecraft Java 1.20.1 / Fabric 的服务端居民项目。Fabric ID 为 `societybots`，命令空间为 `/botmod`。不要求常规客户端安装本模组。当前处于开发阶段：已提供基础状态命令、已在线 Carpet 假玩家的测试登记和普通聊天点名入口，以及可模拟测试的逻辑内核，尚未接通自动生成或真实经济结算，不建议部署到生产服。

## 居民与能力

- 居民不是管理员。工作、移动、容器权限与交易，最终用居民自己作为操作人重新核验，不借用控制者权限。
- 玩家居民默认跟随或执行主人许可的任务，交易另行授权。独立居民受管理员规则约束，但可自定工作、补给和接单目标。
- 按单合作、长期租用和买断是不同合同，Bot 市场独立于商品市场。现有银行仍是实际资金结算来源。
- 视觉设置、区块与任务预算是独立参数。减轻服务器压力靠区块与并发限制，不靠降低贴图分辨率。
- 核心附有寻路、挖矿及入库、工资、Bot 买断与合作协议的模拟；其中游戏操作、交易、重启恢复的实机适配尚未完成。独立 Bot 购地需管理员在 BotMod 审批，价格或地块变化须重新审批；财物、代保管货物及建造归属目前是核心逻辑，不改 LandMod。

## 构建和扩展

JDK 17：`bash test.sh` 运行核心测试；`./gradlew build` 构建 Fabric 开发版。测试版命令：`/botmod status`、管理员 `/botmod adopt-test <已在线Carpet假玩家名>`。登记只在该次服务器会话有效。正常聊天中 `@名字 你好` 触发回复，无需专用聊天命令。模型接入和数据范围见 [模型适配](docs/model-adapters.md)。未经实机验收不能部署到生产服。

参见 [扩展接口](docs/integration.md)。正式接入先验证一个服务端居民生成、重启后恢复身份、主人权限隔离，再接真实工作与运输。

## 0.1.0-test.2：只读观察与模拟规划
- 管理员站在目标附近执行 `/botmod inspect`：检查水平半径 4、上下各 2 格内已加载的方块，不读箱子内容、不加载区块。报告漏斗送入熔炉/容器、疑似车站、木质码头、带护栏的冰道入口。结果只是线索，不表示物主、可进入或可使用。
- `/botmod plan-test mine|unload|blocked`：在合成场景中测试采矿、卸货和停止，不创建任务、不破坏方块。开启 Ollama 时请求异步执行，使用 JSON schema 和目标白名单；无模型、回复无效或超时时回退到规则，执行者换位置或权限取消时丢弃结果。命令反馈仅给发起人或控制台。
- 建筑识别本版只运行规则，不上传建筑数据，不接真实模型建筑分类；规划本版只输出测试建议，不控制居民。

## 0.1.0-test.3：收费区与居民属性
- `/botmod inspect` 通过现有银行收费快照接口读取收费区几何，不读取旧 JSON 作替代、不修改收费模组或银行账本。通过平台和轨道/船道的线索关联同一维度且落在收费范围内的上下车位置，区分「收费站候选」和「收费点（此处未发现上下车线索）」。宽收费区可在中心点以外识别。无法读取快照时显示状态未知，不把它当免费。分类是附近观察，不证明是否开放、是否扣费或能否实际乘车。
- 管理员用 `/botmod traits <已登记机器人>` 查看勤劳、谨慎、探索、社交、经商。评分 0–100，同一个 UUID 一直保持同一组默认值，即使重启后重新登记也不变。没有职业锁定、成长或手调功能。属性仅影响聊天与模拟规划的偏好，不授予操作权限。
- `/botmod plan-test preference <已登记机器人>` 在采矿和卸货都可以的同一模拟场景中验收偏好。勤劳高于谨慎则更愿意继续采矿，否则优先卸货。仓库满、安全矿区不可用等限制优先级高于性格。

## 0.1.0-test.4：实体柜台交互
- 用 OP 执行 `/botmod counter-test <已登记Bot> <bank|shop|market>`。从 **Bot 本人的位置**查找实体柜台，与原模组登记的网点、坐标和维度匹配。Bot 必须在线、存活、非旁观、无 OP，在柜台四格内且射线无阻挡；底座不存在、区块未加载、网点已撤或版本不兼容时拒绝。
- 验证通过后，Bot 以自己的身份使用原网点右键回调。这个命令不传送、不代买、不转账。Bot 的实地自主步行和菜单交易还未接通；测试时先将 Bot 放在柜台附近。不用银行管理员模式。
- 新交易接口绑定单次到场凭证：服务、动作、报价/请求、居民身份和网点部署都要匹配，确认前重新核验位置。商店、市场与领地的核心模拟已应用这道门槛。真实结算适配未启用。
- 建房仅预留 `BuildingPlans` 接口：附属 Bot 可按主人请求出蓝图；独立 Bot 可因缺少住处提出小屋蓝图。未开放实际建造、写入世界或自动拿材料。

## 0.1.0-dev.5（开发中，未发布）

- 按当前规则，不增加柜台，不要求 Bot 打开界面。沿用 `counter-test` 命令做只读到场诊断，支持 `bank|shop|market|arcade|arcade_table`；不会触发右键、打开 GUI、调用旧交易指令或扣款。两个游艺场所分别校验，游艺桌不能作为兑换柜台。
- 管理员 `/botmod traits <Bot>` 多显示「贪婪」（0–100）。决策只在启用、有自主权和授权、没有紧急任务、满足冷却与余额限制的情况下考虑游艺。以 0–99 的随机值比较阈值，0 从不考虑，100 在其他条件通过时总是考虑。此处是决策内核，不是下注权限或实际自动游玩。
- 真实寻路到场、柜台收付、桌上玩法和账本联调仍未完成；开发改动不会调用游艺厅旧远程指令，不包含私有项目源码。以上只读诊断代码尚待 Fabric 编译和实服联调。
- Bot 执行身份只允许已登记的普通玩家会话。进入 OP 列表或切换为创造、旁观后，拒绝 Bot 执行；人类的配置与审批不转移任何权限。

### 生存约束、出生点和防重复提交

- 只允许生存模式。纸面模拟计划不能用来操作世界；真实计划和到场凭证需要当前 Bot 的会话身份，确认失败后该凭证失效。
- 首次出生点选择：有管理员指定时只检查指定维度/坐标，否则检查世界出生点。只接受已加载、有安全地面和站立空间、普通玩家可进入且不挖不搭能走出去的位置。无安全点则不生成。位置不授予挖掘、放置、拿取和建造权限，也不用于传送现有 Bot。此版新增的是选择规则，尚无生成命令或配置界面。
- 收付引用由同一个订单贯穿到场和结算。已有完成回执的订单不得重复执行；扣款或记账结果不明确时先查账，不创建新编号重扣。与服务端银行及库存账本的集成尚未完成。
